# Role in the KB: A fixed review rule can use lessons from new incidents only if it can identify when they apply

## Role
Every visible dependent cites this path as the KB's anchor claim that "Continual learning requires governing behaviour-changing writes, not just storing content". They use it as a premise or edge target: retained changes that alter behaviour need validation, authorization, regression checks and rollback, and readable artifacts differ from distributed-parametric learning. The current text makes a different, narrower claim: a fixed "check past incidents" review rule can use new incident lessons, but only if the reviewer recognizes when a lesson applies. It illustrates this with a citation-independence example. No visible dependent gets what it links for, so the note currently plays no role its dependents rely on.
Relied on: continual learning as durable, evidence-responsive behaviour change rather than stored knowledge; governance of behaviour-changing writes (admission, authorization, regression validation, reversal); readable-artifact versus distributed-parametric split; "a regression-validation requirement"; durability rather than weights as the criterion. None of these appears in the note. Unused: the fixed-rule claim; the citation-independence example; the test that the reviewer distinguishes apparent corroboration from independent support; "The incident shows what the review must distinguish, not that the review rule must change".
