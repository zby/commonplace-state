# Review

## Qualifiers in the central claim

The qualifiers come from the title, description, opening and claim-mode statement:

- "for focus";
- "bounded LLM context" and "bounded effective context";
- a competing workload "whose live state does not fit beside task-solving context";
- "live" in the comparison set;
- "stateless" in the human contrast;
- the restriction to relational rather than intrinsic prioritization.

## Deletion test

- **Bounded context / non-fitting workload.** Without it the claim is false. The Scope section says that on a task fitting in one window the conflict disappears. Load-bearing.
- **For focus.** This names why isolation is chosen, the pressure the opening derives from per-window feasibility. Without it the conflict would have no cause. Load-bearing.
- **Live.** The static-rules argument depends on it: static rules can encode previously named priorities but not live relative scale. Load-bearing.
- **Relational vs intrinsic.** This is the boundary that excludes validation failures and hard invariants. Load-bearing.
- **LLM / stateless.** The human-specialist contrast uses this: humans carry an ambient cross-project model, and stateless agents do not. The LLM wording therefore does real work rather than being only domain scoping.

No qualifier narrows the central claim without doing work in the argument.
