# Review

The central claim is that a better-factory claim compares operative states (the predecessor and the installed successor) under an assessment relation declared before the development it judges. The note gives a mechanism for each element:

- **Operative states rather than candidates.** A discarded candidate never affects later production, so an improvement claim about the factory must concern what is installed and depended on. If the premise is varied so that candidates count, an improvement could be read off a construction event that changed nothing. The conclusion depends on this premise.
- **Antecedence.** Choosing dimensions and thresholds after seeing the result permits selecting requirements the successor happens to satisfy. If declaration happens after the result, the stated guarantee (no post-hoc selection) fails. This premise also carries weight. The note also marks what antecedence does not deliver: it does not make the requirements the right ones.
- **Scope-indexed non-regression.** Without a declared scope, the comparison cannot say which losses would make it fail. The factory-development consequence is derived conditionally: it follows only if that path is in the checked scope. This premise can be varied: under a relation that permits retirement, the consequence is explicitly said to lapse.
- **Improvement, retention and learning.** The three cases are separated by which link is missing, and the learning case requires a contrast that tests the causal contribution.

The claim can be falsified in the ways a framework claim can. For example, a case where a properly declared operative-state comparison still licenses a post-hoc selected verdict would count against it. Its mechanisms are hard to vary. The one thinness is that the title claim is partly stipulative, as the retrospective-criterion concession shows (INFO).
