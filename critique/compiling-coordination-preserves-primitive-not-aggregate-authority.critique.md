# Critique: Compiling coordination into side-effect-free workflows expands capacity, not authority

**Note:** kb/notes/compiling-a-coordination-strategy-expands-capacity-not-authority.md
**Central commitment:** Compiling a coordination strategy into a sandboxed, side-effect-free workflow expands the system's computational capacity (state, window, agent count, duration) while preserving the authority boundary, because the compiled artifact holds no side-effect channels of its own and must delegate every real-world effect through channels the un-compiled prompt already had.
**Critique mode:** claim

## Strongest case against it

The opposing stance is the **capability-security position** — the view of anyone who treats *rate, volume, duration, and aggregate* as part of the threat model rather than as "bookkeeping" (the operational practice behind rate limits, quotas, blast radius, and dwell-time analysis). Call its proponent the *capability auditor*. Their claim is blunt: **the note treats escaping the single-context envelope as a pure capacity win, but that same envelope was a security control. It bounded not just how much the coordinator could *compute* but how many effectful actions it could *emit*. Capacity and authority are not on separate axes — they share that bound, and compilation's entire value proposition is trading it away.**

Their reasoning:

1. **The context envelope did double duty.** A single inference turn / single context window caps two things at once: how much the coordinator can compute (capacity) and how many delegated calls it can emit before the turn ends (aggregate exposure). The note enumerates the capacity gains — *"store state across steps, exceed a single context window, coordinate many agents, and run far longer than any single inference"* — and routes every one of them to the "capacity" axis. But each is also a magnitude-of-harm dimension: exfiltration size, resource exhaustion, sustained dwell, rate-based-detection evasion, brute force. You cannot bank the removed bound as a capacity gain and simultaneously deny it any authority consequence. It is the *same bound* described twice.

2. **A per-call permission gate does not bound aggregate effect.** A delegated channel governed by a permission model is governed *per call*; it is almost never governed *per aggregate*. "Delete one file when asked" and "delete files in a loop until the tree is empty" are the same primitive and wildly different authorities. A single conversational turn makes a handful of delegated calls; a compiled workflow can loop 1,000 agents (the documented cap in the dynamic-workflows note), run for hours, and repeat a delegated effect ten thousand times. The note's clean separation survives only by silently adopting a per-call notion of authority that the threat model rejects. At the limit, capacity *is* authority: the power to drive a delegated channel at machine scale and persistence is a power the un-compiled prompt did not practically have.

3. **"Channels the un-compiled strategy already had" equivocates on reachability.** The note's escape hatch is "the prompt could already call these." Could it — reliably, at this volume, this persistence, holding this much intermediate state? No. The note's *own capacity argument* establishes that the prompt-driven form cannot hold state, exceed a context window, or run long. So the note argues, on the capacity side, that the compiled form reaches what the prompt never practically could, and on the authority side, that it reaches nothing new. Both about the same artifact. Security cares about practical reachability, and by that standard the boundary moved.

4. **The note's own escape hatch concedes the gap.** Open Question #2 rules delegate-side enforcement out of scope. So the preservation guarantee holds *only if* every delegated channel is independently rate-, volume-, and duration-bounded — a strong, undefended assumption. The documented dynamic-workflows case (per-call permission only, inherited session allowlist, 1,000-agent cap, multi-hour runs) is precisely where it is not.

The auditor's positive thesis: **authority is the practically reachable set of world effects. The single-context envelope bounded that set; compilation removes the bound. The primitive action alphabet is preserved, but aggregate-effect authority expands — and it expands along the very axis the note files under "capacity," because capacity and authority shared that one bound.**

## How the note engages it

**Unengaged on the core, and structurally foreclosed.**

- On the shared-bound argument (moves 1–3): **unengaged.** The note *asserts* orthogonality (*"two properties... different sources," "Authority is a separate axis"*) as a premise, not a conclusion — the thing to be proven, stated as a given. It enumerates duration, agent count, and scale on the capacity side and never asks whether those same dimensions are authority dimensions. It had the data in hand and routed all of it to one axis by stipulation. The closing line — *"the compiled form can reach the world by paths the prompt never could"* — is said *only* about lifting the sandbox, but the auditor's point is that it is already true *within* the sandbox, via scale and persistence over a per-call gate.

- On the delegate-enforcement scope (move 4): **genuinely engaged, but against a weaker objection.** The note honestly scopes the guarantee "relative to those agents' allowlists" (the "narrower than a whole-system safety claim" paragraph and Open Question #2). But that answers *inherited bad allowlists* — a different and weaker objection than aggregate abuse of individually *correct* per-call allowlists. Scoping to delegate enforcement does nothing against an attack that assumes each delegate is per-call-correct and exploits the aggregate.

## Constructive findings

- **Name the shared bound and retitle around it.** The note's value is real — the sandbox blocks *new primitive channels* and forces delegation — but "capacity, not authority" overclaims because the single-context envelope it escapes was bounding both. The defensible claim is narrower and more interesting: *compilation adds no new primitive effect channel, but it expands the practically reachable effect set through scale and persistence; primitive-authority is preserved, aggregate-authority is not.* Convert the note from "capacity not authority" (false) to "primitive-authority preserved, aggregate-authority expanded" (true).

- **Defend the orthogonality as a theorem or drop it.** Right now orthogonality is asserted. The preservation claim is real only for channels whose per-call authorization already bounds their aggregate use — *non-composable, per-call-saturating* channels. If the author wants to keep a preservation result, it must be stated for that channel class explicitly, and the note should concede that the documented dynamic-workflows case is not in it.

## Secondary objections (optional)

- **Composition is the *weak* version of this attack, not the strong one — and for this system it largely fails.** One might argue that sequencing read-secret then network-post manufactures exfiltration the parts lacked. But the prompt-driven coordinator already bridges isolated agents — it reads result A and passes it to B across turns — so the read→post *trajectory* was already reachable in the interpreted form. Composition manufactures new authority only where inter-agent isolation was itself the security boundary, which is not the case here. The compiled form makes the trajectory cheaper and more repeatable, but "cheaper and more repeatable" is the *scale* argument above, not an independent composition argument. Treat composition as a special case of aggregate-authority expansion, not a separate finding. (Open Question #3 names this; it should be folded into the aggregate-authority point rather than left standing as if it were a distinct, open mechanism.)

- **The compiler analogy leaks on authority too, not only capacity.** The note insists the analogy is "*exact* on authority." But real optimizing compilers change effective authority — dead-store elimination removing a `memset` that zeroed a secret is a shipped security regression. "Compilation preserves semantics" fails at exactly the edges that matter for security. The note borrows the analogy's reassurance on the one axis where it is least trustworthy.

- **"Side-effect-free" is overstated for the script even before delegation.** The script consumes a shared `budget`, schedules concurrent agents up to a hard cap, and journals results — observable resource effects (token spend, concurrency, wall-clock) that are themselves abusable (denial-of-wallet, resource exhaustion). "No filesystem, shell, or network API" is not "side-effect-free," and the gap is another place capacity quietly carries authority.
