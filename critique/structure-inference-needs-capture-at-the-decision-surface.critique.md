# Critique: Bottom-up structure inference needs capture at the decision surface, not the state

**Note:** kb/notes/structure-inference-needs-capture-at-the-decision-surface.md
**Central commitment:** Bottom-up inference of entities/relations/structure from traces is feasible only if capture is decision-shaped (inputs referenced, constraints, exception path, approval, action, outcome) rather than state-shaped (the changed row, the final value), because the "why" behind a decision is cheap to record at the moment of decision and decays toward unrecoverable once only the resulting state remains.
**Critique mode:** claim

## Strongest case against it

**Who holds it:** a practitioner grounded in the process-mining / decision-mining research program (van der Aalst and successors) and, more broadly, anyone who does rule/invariant extraction from execution traces (e.g., Daikon-style dynamic invariant detection) — the same family of technique this note's own companion, `spec-mining-as-codification.md`, names as "the mechanism."

**The reasoning:** Decision mining is a mature, production-deployed subfield built on exactly the premise this note says is infeasible. Its input is an event log: activity name, timestamp, case ID, and a handful of case attributes present at each point (e.g., loan amount, customer tier, queue length) — this is state-shaped by the note's own definition: it records that a case reached a state and what data accompanied it, not an explicit rationale ("which policy bound it," "who approved," "why the exception fired"). No decision receipt is ever written. Yet decision-mining algorithms routinely recover the branching *rule* — the decision tree or guard condition that governs which path a case takes — with useful fidelity, by correlating case-attribute values against which branch was empirically taken across many instances.

The move that defeats the note's locality argument is a level shift the note doesn't consider: the "why" of any *single* instance is indeed unrecoverable from that instance's endpoint state alone — the opponent concedes this much. But bottom-up **structure** inference (the note's actual target: entities, relations, rules — not "what happened in case #4821") is a population-level task. Across enough state-only instances, the correlation between input state and outcome *is* the decision rule; you do not need any individual case to carry its own rationale, because the rationale is exactly what the aggregate regression/decision-tree fit recovers. This is the same logic underlying all supervised rule extraction: you never need a label for *why* a training example got its label, only enough labeled examples for the boundary to become statistically visible. The note's central move — treat "why" as a substance held once, at one moment, by one process, decaying afterward — is the wrong ontology for it; the discipline's practice shows "why" (at the level of a general rule) is a pattern *distributed across* many endpoint-only instances, recoverable by correlation rather than by receipt.

If this holds, "decision-shaped capture" is not a *necessary* precondition on bottom-up inference — it is one route to it (a cheaper one, granted, and one that also recovers instance-level why, which population inference cannot). But "only if" is the note's claim, and decision mining is a working counterexample to necessity, not merely an alternative to convenience.

## How the note engages it

**Partially engaged**, and only at the meta-level, not with the specific mechanism.

- Paragraph 2 of "Open Questions" (line 32) already flags almost exactly this shape of objection in the abstract: *"Can partial 'why' be reconstructed from rich enough event logs (not just final state)? If so, the dichotomy is really a continuum along how close the capture point sits to the decision, and 'state vs decision' is the two ends of it."* This anticipates that state-shaped logs might carry recoverable structure and explicitly concedes the dichotomy could collapse into a continuum — so the note does not claim ignorance of the possibility.
- But it is filed as an **open question**, not resolved or defended against. The note gives no account of *why* the continuum wouldn't undermine "necessary," and — critically — it frames the recovery question only at the single-instance level ("partial why... reconstructed from... event logs"), never at the population/aggregate level where decision mining actually operates. The specific mechanism that defeats the strict per-instance locality argument (cross-instance statistical correlation recovering a general rule without any instance carrying its own rationale) is not named or considered anywhere in the note.
- `history-has-one-chance-to-become-checkable.md` (cited as the note's parent claim) does address a cousin of this objection at its own level — "Leakage is real but unreliable... noisy and adversarially fragile, so a review contract cannot bind on it" (its Boundaries section) — but that is a claim about *unreliability of individual leaked traces*, not about the statistical recoverability of a *general rule* from many state-only instances, which is a different and stronger claim than "leakage happens." This note does not inherit or adapt that boundary for its own, more specific mechanism claim.

## Constructive findings

- Resolve the flagged Open Question rather than leaving it open: state explicitly whether the claim is about **recovering a specific decision's rationale** (where the locality argument is strong and, as far as this critique goes, unrebutted) or about **recovering the general decision rule/structure** (where decision mining is a working counterexample to "only if"). The note currently equivocates between these two scopes — the title and abstract say "structure," the body's examples and reasoning are about individual decisions ("who signed off," "what it chose").
- If the note narrows to "faithful recovery of the *specific* rationale behind each instance," the process-mining counterexample mostly falls away (aggregate rule discovery doesn't tell you why case #4821 specifically was approved) and the claim becomes much more defensible — but then the note should say so, since "spec mining," its own named mechanism, is explicitly a population-level technique that thrives on exactly the kind of state-shaped, multi-instance data the note says can't support it.
- Consider addressing the tension noted in `spec-mining-as-codification.md` itself: its worked example ("parsing dates, normalising names, mapping intents to actions, detecting escalation triggers") mines specs from *I/O behavior* — inputs and outputs, not explicit decision receipts with constraints/exceptions/approvals. If spec mining (the mechanism this note leans on) already works over state-shaped behavioral traces in that companion note, this note owes an explanation of why its own capture-position requirement is stricter than the mechanism it cites actually needs.

## Secondary objections (optional)

- **The fix smuggles back the thing it opposes.** The note frames itself as sharpening "structure earned, not imposed" (paragraph 2), but requiring capture to be decision-shaped — inputs, constraints, exception path, approval, action, outcome — is itself an upfront schema commitment, prescribed before any instance occurs. An opponent could argue this quietly reintroduces the very "prescribe a world model upfront" move that trace-derived inference was supposed to avoid; the note could defend this (the six-field record shape is a generic recording template, not the target domain ontology — entities/relations are still inferred *within* it) but it doesn't currently make that distinction explicit.
- **Overlooked correlated-multi-stream recovery.** The note's locality argument implicitly assumes a single trace stream per decision. In practice, many systems recover "why" forensically by correlating *multiple* state-only streams (e.g., an inventory adjustment correlated against a concurrent support ticket, or a database change correlated against a calendar entry or an email thread) — none individually decision-shaped, but jointly reconstructive. This is weaker than the decision-mining objection (it's ad hoc and per-case, closer to the "leakage" boundary already named in the parent note) but it's a real gap in the "decays toward unrecoverable" framing, which reads as reasoning over an isolated single stream.
