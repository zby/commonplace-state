# Premise decomposition: A better-factory claim compares operative states under an antecedent assessment relation

**Note:** `kb/notes/a-better-factory-claim-compares-operative-states.md`  
**Register:** claim  
**Central commitment (one sentence):** A determinate claim that a software factory became better compares a predecessor state with an operative successor state under an antecedently declared, scope-indexed assessment relation, and it declares evaluator location separately from the learner boundary.

## Premises and counterexamples
1. **Experience-responsive retention is silent about quality, so improvement must be asserted by a separate comparison claim.** — HOLDS — Active hunt found no concrete case where the mere fact that production experience caused a retained reusable change establishes that the retained change improved the factory; cases where "retention" is defined as beneficial adaptation change the upstream definition rather than defeating this note's premise.
2. **A better-factory claim is indeterminate unless it fixes the compared states, the assessment relation, the successor route, and evaluator location.** — DOUBTFUL — A tightly specified experiment or deployment protocol can make all four values recoverable without restating them inside the improvement claim; the claim may be determinate by incorporation from the protocol rather than by explicit declarations in the note's sense. — LOCAL — instance
3. **The improvement claim's endpoints are the predecessor and the operative successor, not the retained change, construction event, or uninstalled candidate.** — DOUBTFUL — Candidate-admission workflows often make the decisive "this candidate is better than the current factory" comparison before installation; if that pre-installation judgment is itself treated as the better-factory claim rather than only as an adoption gate, an uninstalled candidate is a comparison endpoint. — GLOBAL — instance
4. **An assessment relation must be declared before the judged development because a relation chosen after seeing the successor can make any difference look favorable.** — DOUBTFUL — A retrospective relation can still be non-arbitrary when it comes from an independent source, such as a newly imposed compliance rule or operator objective that was not selected to fit the observed successor; such a claim is not antecedent to development but can remain falsifiable. — GLOBAL — instance
5. **A valid assessment relation includes non-regression thresholds over the predecessor's prior scope and excess over a specified target on at least one named production dimension.** — DOUBTFUL — A factory can be better under an explicitly accepted tradeoff relation that drops an obsolete, unsafe, or low-value prior capability while greatly improving a more important production dimension; that defeats non-regression as a necessary component of every better-factory assessment. — GLOBAL — instance
6. **Indexing non-regression to the predecessor's prior scope is what prevents "no worse" from becoming either unmeetable or vacuous.** — HOLDS — Active hunt found no alternative reading that avoids both extremes as cleanly: "no worse at everything the successor might face" is too broad, while "no worse at whatever the successor still attempts" lets regressions disappear by redefining scope.
7. **When factory development is in the predecessor's prior scope, non-regression requires the successor to preserve an applicable operative path for later factory development.** — HOLDS — Active hunt found only cases where factory development was not actually in prior scope, was deliberately traded away, or was preserved by a different mechanism; none defeat the conditional premise once non-regression over prior scope is assumed.
8. **Preserving a factory-development path is weaker than proving compounding improvement.** — HOLDS — Active hunt found no case where retaining an applicable path for later revision entails that later retained changes will actually improve the factory; the later-episode test remains separate.
9. **The compared factory states span the deployed production machinery rather than model weights alone.** — HOLDS — Active hunt found cases where model weights stay fixed while prompts, tools, tests, workflows, or evaluators change the factory's production behavior; these support the premise rather than defeat it.
10. **Measurement over snapshots and candidate admission produce the same kind of endpoint comparison, but they differ in whether evaluation determines the successor or describes an already realized one.** — DOUBTFUL — Canary releases and staged rollouts can make a change temporarily operative while evaluation still decides whether it remains installed and becomes depended on; the measurement/admission split can misclassify mixed episodes unless the successor route is narrowed. — LOCAL — instance
11. **Evaluator location is not recoverable from the learner boundary and must be declared separately.** — DOUBTFUL — If the learner boundary is defined operationally as the set of mechanisms whose judgments determine retained state, an admission-gating evaluator is inside the boundary by definition; a separate evaluator-location declaration may be redundant under that boundary convention. — LOCAL — instance
12. **A measurement made only after a realized update does not by itself put the measurer on the causal update path for that episode.** — HOLDS — Active hunt found future-feedback and rollback cases, but those add a causal retention or later-update role; a purely after-the-fact measurement does not cause the already realized update it measures.
13. **Passing the better-factory comparison does not establish factory learning at the declared boundary.** — HOLDS — Active hunt found straightforward cases where an external builder produces a better successor from supplied specifications without predecessor production experience causally entering the retained change.
14. **Experience-responsive retention does not establish that the better-factory comparison passed.** — HOLDS — Active hunt found straightforward cases where retained changes caused by production experience degrade the factory or improve it against an objective other than the declared comparison.

## For the human
Look first at premise 5: if better-factory claims can be explicitly tradeoff-shaped, non-regression over predecessor prior scope is too strong as a necessary condition.
