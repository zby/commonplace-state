# Premise decomposition: A domain-priced exception does not refute an idealization

**Note:** kb/notes/a-domain-priced-exception-does-not-refute-an-idealization.md
**Register:** claim
**Central commitment (one sentence):** For a defeated crisp or exclusive claim whose unification is worth retaining, recasting it as an idealization is legitimate, and an exception does not refute that idealization, when independent domain practice already prices the exception and the exception is marked, bounded, and subordinate rather than ordinary or dominant.

## Premises and counterexamples

1. **Domain pricing is sufficient to decide whether an exception refutes an idealization, without the model's intended use supplying a separate condition.** — DEFEATED — A database-schema migration is priced through separate tooling, a changeset, review, and an infrequent execution path. Treating it as a correction can be harmless in a steady-state query-cost model, but omitting the same migration is fatal to a deployment-compatibility model because migrations determine whether old and new application versions can operate against the schema. The domain practice and its pricing are unchanged while the exception's status as a refuter changes with what the model is for. — GLOBAL
2. **A defeated crisp or exclusive claim whose unification is worth keeping is eligible for idealization rather than a repair that weakens its original force.** — DEFEATED — Consider the security claim “a non-administrator can never decrypt a production record.” A separately permissioned, approval-gated, audited break-glass path that lets an incident responder decrypt one record is marked, costly, rare, bounded, and subordinate, yet that one path refutes the safety guarantee. Calling the guarantee an idealization changes it into a normal-operations model; it does not retain the crisp commitment. — GLOBAL
3. **The relevant domain and its ordinary practice can be identified independently enough that whether an exception is priced does not depend on a convenient domain boundary.** — DOUBTFUL — Reflective class mutation may be condemned as monkey-patching in ordinary Python application code but used as a normal construction mechanism inside a metaprogramming framework. Both communities belong to the language domain, and the note gives no rule for selecting the practice whose marks and norms control the verdict. — GLOBAL
4. **“Bounded” and “subordinate” have determinate comparison bases across the qualitative domains to which the criterion applies.** — DOUBTFUL — An escape hatch can be invoked in one run, occupy few lines, and incur a measurable slow-path charge while having unbounded semantic reach because it can replace future dispatch behavior. Frequency, code volume, runtime cost, and causal importance give different answers, but the criterion specifies no measure or threshold. — GLOBAL
5. **Pricing attested before a counterexample is raised against the claim is independent of the claimant rather than an earlier immunizing convention.** — DEFEATED — An API designer can ship a deliberately named `unsafeEscape` interface and then claim that the API excludes unsafe behavior; the marked interface predates a critic's counterexample but was created and controlled by the same claimant. Temporal priority alone does not establish independent attestation. Requiring adoption or evidence not produced by the claimant would repair this test without discarding the domain-pricing idea. — LOCAL
6. **The five listed signatures, without a combination or threshold rule, discriminate exceptions from ordinary domain practice.** — DEFEATED — Every production deployment in a regulated organization may require a changeset and review sign-off, so governance ritual can mark the ordinary path; allocation and I/O impose runtime charges while remaining ordinary operations; and the existence of a rival paradigm shows that a commitment is contestable, not that a particular practice is exceptional inside the original paradigm. The signature list needs narrower meanings or an evidentiary rule. — LOCAL
7. **An idealization can retain a crisp first-order model and remain refutable by making markedness, boundedness, and subordination of its conceded deviations part of its content.** — HOLDS — The counterexample hunt found ad hoc models whose authors call every failure a correction, but those models lack the stated higher-order commitments; once those commitments are explicit, an erratic, unbounded, or dominant deviation can still contradict the idealization.
8. **An exception that is genuinely ordinary and unmarked inside the declared domain, or whose mechanism carries more of the target behavior than the first-order model, refutes the idealization.** — HOLDS — Apparent counterexamples involved common effects that were nevertheless explicitly represented and bounded, or models scoped to a target those effects did not dominate. When ordinary unmarked practice or a dominant correction remains inside the declared target, the first-order account misdescribes that target.

## For the human

Look first at premise 1: the same independently priced migration can be negligible for a steady-state model and decisive for a lifecycle model, so decide whether intended use must join domain pricing as an explicit discriminator of refutation.
