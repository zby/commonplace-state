# Premise decomposition: Model-resolved indirection adds interpretation work to LLM execution

**Note:** `kb/notes/model-resolved-indirection-adds-interpretation-work-to-llm-execution.md`
**Register:** claim
**Central commitment (one sentence):** When an instruction reference is resolved by the model, resolving its binding adds interpretation work to LLM execution.

## Premises and counterexamples
1. **A reference can be resolved either by the model or by a surrounding shell, harness, or tool, and those are different execution paths.** — HOLDS — Shell expansion of `$PROJECT_ROOT` after model emission and model production of a literal from `{{project_root}}` are concrete witnesses; no defeater to the distinction was found.
2. **For a reference to count as model-resolved, the model must use binding information in its effective context, or enough information there to infer it, in addition to the reference occurrence.** — HOLDS — Prior-turn context, retrieval results, and tool results are candidate sources, but once the model uses them they are information in its effective context; a case with no such information would fall outside the note's definition rather than defeat it.
3. **A model-resolved reference requires the model to identify the reference and produce or apply a value consistent with its binding, whereas delivering the literal does not require that binding operation.** — HOLDS — A model that only passes an alias to a deterministic resolver is executor-resolved, not a counterexample; active hunting found no in-scope model-resolved case that avoids connecting the reference to its binding.
4. **Natural-language instructions without a surrounding formal resolver do not guarantee a runtime dereference procedure equivalent to conventional code's resolution.** — DOUBTFUL — An explicit prompt can describe a replacement algorithm and a model can sometimes follow it reliably, so the note's “no equivalent procedure” contrast is too broad unless “formal” means an externally enforced guarantee; the remaining model interpretation would still support the central commitment. — LOCAL — instance
5. **When the model resolves a reference, the binding and each use impose a structural burden on the model-facing context and execution even when the alias is shorter than the literal.** — HOLDS — A short alias using fewer tokens is an explicit counterpressure, but it does not remove the need to carry or infer the binding and connect it to each use; no in-scope case removed that structural obligation.
6. **A model-side resolution attempt can produce an unresolved placeholder, a malformed value, or a wrong binding.** — HOLDS — Constrained decoding or an executor-side check can catch or prevent some failures, but that adds a correction layer or moves the relevant substitution outside the model; no in-scope counterexample eliminated the raw model-side failure surface.
7. **The relevant comparison is between complete delivered forms and includes token, authority, binding, failure, maintenance, and regeneration costs rather than treating “literal” and “variable” as isolated syntax.** — HOLDS — A short alias can beat a long literal on tokens, while executor expansion can preserve one live authority and generated literals can add drift work; these cases support the complete-form comparison rather than defeat it.
8. **Upstream resolution relocates semantic work to the assembler or executor rather than eliminating it.** — DOUBTFUL — A build step can mechanically copy an already authoritative string into an ephemeral prompt, removing model-side interpretation without making a new semantic classification or choice; whether the pre-existing binding counts as relocated semantic work is unresolved. — LOCAL — instance
9. **Literalization is the right choice when the assembler knows the authoritative value, the value is stable for the validity window, the model must use it itself, and the complete literal's token and maintenance costs do not exceed the binding and failure costs removed.** — DOUBTFUL — A stable setup-known secret can satisfy all four conditions yet should remain an executor-side alias to avoid exposing it in model context, logs, or prompt caches; security and authority-boundary costs are not named in the comparison. — LOCAL — instance
10. **Variation between invocations does not by itself require a model-facing placeholder because an assembler can inject the current file, URL, or query before each model consumption.** — HOLDS — A per-invocation assembler that reads the current value and inserts it into the prompt is a concrete witness; cases where the model must choose or reason over the value are separately conditioned in the note.
11. **Generated instructions necessarily create a derived-copy validity and regeneration or drift obligation.** — DEFEATED — A one-shot assembler can expand a template in memory, send the prompt immediately, and discard it, leaving no retained derived copy that can drift or require regeneration checking. — LOCAL — instance

## For the human
Inspect premise 4 first: the contrast with conventional code still relies on an unproved boundary between a model-followed natural-language replacement procedure and a formally enforced resolver.
