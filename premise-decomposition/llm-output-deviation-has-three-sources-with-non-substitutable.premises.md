# Premise decomposition: LLM output deviation has three sources with non-substitutable remedies

**Note:** kb/notes/llm-output-deviation-has-three-sources-with-non-substitutable.md
**Register:** claim
**Central commitment (one sentence):** For a fixed assembled input, an unwanted LLM output should be diagnosed by three distinct relations — `V` wider than `I`, `D` placing mass outside `V`, and the spread of `D` across runs — because prompt narrowing, error correction, and sampling control address different primary surfaces and so are not complete substitutes.

## Premises and counterexamples

1. **For a fixed assembled input, the phenomenon can be modeled by an intended set `I`, a valid set `V`, and a produced distribution `D`.** — HOLDS — The hardest cases were graded or partially ordered preferences, but once the note's own scope cut excludes cases where the user cannot say what counts as acceptable, an active hunt found no concrete output-deviation case that required a fourth object rather than a different acceptability threshold.
2. **Within that scope, underspecification (`V` extends beyond `I`), interpreter failure (`D` places mass outside `V`), and indeterminism (the spread of `D`) are genuinely different relations rather than three names for one phenomenon.** — HOLDS — A deterministic but conforming interpreter can still realize `V ⊃ I`; a deterministic non-conforming interpreter can produce out-of-`V` outputs even when `V = I`; and a stochastic interpreter can vary between acceptable and unacceptable points without changing either boundary, so the hunt found no case where the three relations collapse once `I`, `V`, and `D` are kept distinct.
3. **Once the assembled input is fixed and the user's intent is known, these three relations exhaust the in-pipeline sources of output deviation that matter to this diagnosis.** — HOLDS — Wrong retrieval, stale memory, and bad tool results looked like candidate fourth causes, but in each case they changed the assembled input upstream rather than adding another relation inside the fixed `specification → interpreter → sampled execution` pipeline.
4. **Prompt narrowing primarily changes `V` relative to `I`, error correction primarily changes which outputs survive relative to `V`, and sampling control primarily changes the concentration of `D`.** — HOLDS — Cross-effects are real, but the counterexample hunt found no concrete case where a purely lower-temperature move narrowed `V`, or where a checker rejected valid-but-unwanted outputs without some representation of the missing intent entering the checker or selector.
5. **Because the remedies target different relations, changing one relation does not in general repair the others.** — HOLDS — Lower temperature can concentrate on an invalid or unwanted point, and validation can perfectly enforce `V` while still leaving `V ⊃ I`; the hunt found no complete substitute unless the "substitute" also imported the missing narrowing, checking, or selection work by another route.
6. **The note's listed "narrowing" examples can be treated as one remedy family for the non-substitutability claim.** — DOUBTFUL — "Constraining part of the task to code" is not just a stronger prompt: for the constrained subtask it can collapse `V` to a chosen semantics, eliminate out-of-`V` behavior by using a different interpreter, and remove sampling variation entirely, so this example behaves more like substrate replacement than ordinary prompt narrowing. — LOCAL
7. **The empirical signatures given are strong enough for practical triage between the three relations.** — DOUBTFUL — Stable failure does not separate underspecification from interpreter failure, and the competent-reader test is contestable exactly on borderline specs where routing matters most, so the signatures are useful heuristics but weaker than the taxonomy itself. — LOCAL

## For the human

Look first at premise 6: decide whether "constraining part of the task to code" belongs in the same remedy bucket as prompt narrowing, because that example is the cleanest place where the note's non-substitutability framing overreaches.
