# Premise decomposition: Codifying predictable choices leaves agents with less predictable work

**Note:** kb/notes/codifying-predictable-choices-leaves-agents-with-less-predictable-work.md
**Register:** claim
**Central commitment (one sentence):** When a system moves the more operationally predictable recurring choices from agent discretion into symbolic controls, the remaining work left to agents becomes less predictable in that same operational sense even if the surrounding domain is deterministic.

## Premises and counterexamples

1. **A choice can be more or less predictable in an operational sense according to whether its state-to-action mapping and acceptable result can be specified and verified cheaply and reliably enough to replace open-ended judgment.** — HOLDS — Deterministic-state cases with no cheap reliable verifier, and conversely cases with a verifier but no cheaply specifiable mapping, still fit the note's notion; no concrete case found where the notion collapses into mere environmental stochasticity.
2. **Codifying a recurring choice into a schema, validator, program, or other symbolic control removes that choice, or enough of it, from future open-ended agent judgment to change the composition of the residual agent workload.** — DOUBTFUL — Guardrail codifications often fence or veto only a narrow slice of the decision while leaving the agent to perform most of the same diagnosis and action selection as before; such partial codification increases constraint without clearly migrating a distinct workload item. — LOCAL — instance
3. **Under a fixed incoming workload and routing policy, preferentially removing the more predictable choices from agent discretion negatively selects the remainder on predictability.** — HOLDS — Given the antecedent as stated, active hunts through deterministic repositories, fixed datasets, and workflow cases did not produce a case where repeatedly removing the more predictable decisions from the agent-assigned set made the remaining set more predictable without also changing the workload or routing basis.
4. **The note can infer that the residual workload becomes less predictable without specifying a workload-level aggregation rule for predictability.** — DEFEATED — If the codified choices are tiny or rare relative to the remaining work, a time-weighted or frequency-weighted workload measure can stay unchanged while an unweighted per-choice average falls, so "the workload becomes less predictable" is not determined until the comparison metric is fixed. — LOCAL — instance
5. **This residual-predictability shift does not require the surrounding domain to be stochastic, because late-arriving facts, expensive contingency spaces, weak verification, or implementation cost can make a choice operationally hard to pre-specify inside an otherwise deterministic environment.** — HOLDS — Deterministic debugging, repository investigation, and proof search already provide concrete classes where the world state can be fixed while the next economically specifiable and verifiable action remains open-ended; no counterexample found that forces domain stochasticity for the note's operational notion.
6. **Overall system predictability can increase while the agent layer becomes less routine, so improved automation and reduced residual predictability are compatible rather than contradictory.** — HOLDS — Candidate counterexamples where automation reduces agent burden by shrinking task count still leave the remaining agent-assigned slice comparatively harder or more exception-heavy; they challenge effect size, not the compatibility claim.

## For the human

Look first at premise 4: the note's selection effect needs an explicit workload-level predictability measure, or the main conclusion remains underdetermined.
