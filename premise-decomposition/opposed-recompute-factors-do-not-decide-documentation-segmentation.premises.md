# Premise decomposition: Opposed recompute factors do not decide documentation segmentation

**Note:** kb/notes/opposed-recompute-factors-do-not-decide-documentation-segmentation.md
**Register:** claim
**Central commitment (one sentence):** Within the note's stated cache domain and among feasible alternatives, crossed directions in per-reconstruction saving and recurrence determine neither audience cache value nor a segmentation choice, and an optional audience split improves on the best shared arrangement only when audience-fit specialization value repays the split's full incremental burden.

## Premises and counterexamples

1. **For every comparison within the stated scope, document consultation can be matched to source reconstruction at an equivalent output and reliability threshold, and avoided-reconstruction operating value over one horizon can be represented as workload-weighted net saving per reconstruction times the number avoided, less maintenance in the same currency.** — HOLDS — An active hunt considered heterogeneous task costs, retention, source churn, and non-reconstructible documentation: heterogeneous event savings can be represented by a workload-weighted mean, retention and churn change the event count or savings, and the note explicitly excludes non-reconstructible content and scalar comparisons without a defensible common currency.
2. **For all positive savings and recurrence values, if one audience has the larger saving but the smaller recurrence, those two inequalities do not order the products.** — HOLDS — Both product orders satisfy the premises: `10 × 2 > 5 × 3`, while `10 × 2 < 5 × 100`; no counterexample can derive one order from the crossed directions without adding magnitudes.
3. **For every crossed profile covered by the claim, the factor directions alone also do not order net cache value after maintenance.** — HOLDS — Setting both maintenance values to zero preserves the two opposite product orders above, and leaving maintenance magnitudes unspecified adds another free term rather than forcing an order.
4. **For every optional architecture comparison with a fixed objective, output threshold, and feasible set, audience-level cache values do not encode whether one shared arrangement fits both audiences, so segmentation must be compared at the arrangement level against the best feasible shared baseline.** — HOLDS — A hunt through equal-value but representation-incompatible audiences and unequal-value audiences that can consume the same artifact found both configurations possible; the scalar cache values contain no compatibility information that could rule either one out.
5. **Whenever an audience split adds layers to an otherwise unchanged shared baseline, audience-fit specialization value is the only positive incremental term that can make the split preferable, so it must exceed the aggregate incremental costs caused by the split.** — DOUBTFUL — Consider a shared canonical document plus two audience-owned generated layers with identical content and representation: if independent release scheduling removes 10 units of cross-team coordination cost while generation and drift review add 4, the split improves total value although tailoring-based audience-fit value is zero. The note may intend “audience-fit benefit” to include every split-specific operational gain, but its explicit definition as the benefit of tailoring content does not settle that reading. — GLOBAL — instance
6. **Whenever fit and maintenance effects are non-substitutable, no scalar split comparison is available and a declared constraint or decision rule must supply the choice.** — HOLDS — Lexicographic safety, policy, and qualitative-fit cases do not refute this premise: each is precisely a declared rule or feasibility constraint rather than a scalar ordering supplied by the recompute factors.

## For the human

Look first at premise 5: decide whether specialization value includes every positive split-specific effect or narrow the central only-if claim to comparisons in which audience fit is the split's only incremental benefit.
