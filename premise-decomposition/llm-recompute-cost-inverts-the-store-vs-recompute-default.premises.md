# Premise decomposition: LLM recompute cost shifts the store-vs-recompute balance

**Note:** kb/notes/llm-recompute-cost-inverts-the-store-vs-recompute-default.md
**Register:** claim
**Central commitment (one sentence):** For a model-facing derived value whose model-side derivation is costly, that cost shifts the store-versus-recompute economics toward checked materialization, but persistence pays only when the materialized copy substitutes for work and its total expected cost over the stated validity window beats model-side and external on-demand derivation.

## Premises and counterexamples
1. **A materialized answer must eliminate or reduce derivation, discovery, or source-inspection work in order for persistence to pay; a copy that leaves all of that work in place cannot repay its own costs.** — DEFEATED — In a high-consequence decision, a model can perform the full derivation and compare its answer with a separately generated, checked materialization; the copy replaces no work, yet its independent error-detection value can reduce expected failure loss by more than its creation, maintenance, and retrieval costs. — GLOBAL — instance
2. **Every decision-relevant advantage and liability of the three paths can be represented in a commensurable total expected cost, so lower total expected cost is a necessary condition for saying that persistence pays.** — DOUBTFUL — A system with a hard latency, availability, or safety constraint can reject a lower-expected-cost on-demand path and retain a costlier materialized path because only the latter is admissible; the premise survives only if constraint violation is explicitly priced, possibly as an infinite cost, rather than treated as a non-cost requirement. — GLOBAL — instance
3. **Holding the other path costs and delivered answer fixed, increasing model-side derivation cost makes checked materialization more attractive relative to model-side derivation.** — HOLDS — Attempts to reverse the comparison required changing another term, such as answer quality, validation expense, or reuse; with those fixed, increasing one alternative's cost cannot worsen materialization's relative position.
4. **A value that ordinary code can derive cheaply can nevertheless be costly for a model to derive because the model may need context, discovery, tool use, and fallible reasoning that the code path does not need.** — HOLDS — A validator-produced boolean that otherwise requires an agent to locate and sweep many files is a concrete witness; cases where the agent has an equally narrow derivation tool do not refute this existential capability.
5. **Model-side derivation, external on-demand derivation, and persisted checked materialization exhaust the relevant alternatives for delivering the derived answer.** — DOUBTFUL — A hybrid can persist a coarse routing value and then perform a narrowed on-demand derivation only for the selected region; it is unclear whether the note's three paths are meant as composable cost primitives or mutually exclusive strategies, and on the latter reading the hybrid is a fourth alternative that can dominate each pure path. — LOCAL — instance
6. **Persistence creates creation, retrieval, and possible staleness-maintenance costs that expensive model-side derivation does not erase, so model recomputation cost alone cannot establish that materialization is cheaper.** — HOLDS — Immutable sources can drive expected change and invalidation cost to zero, but creation and retrieval remain, and zero-valued terms fit rather than defeat the ledger; no case made the model-side term alone sufficient without comparing the remaining terms.
7. **A deterministic source-bound comparison performed before model consumption, with the copy withheld when comparison fails, is sufficient to keep the materialized value subordinate to the live source.** — DEFEATED — The checker can pass, the live source can change before the model reads the copy, and the model can then consume a stale value; the check-to-use race requires an atomic snapshot, version binding, or equivalent condition absent from the premise. — LOCAL — instance
8. **When materialization is justified specifically by avoided model work, the model must receive an adequate and trusted answer that eliminates at least some of that work rather than merely adding a preliminary read before the same work.** — HOLDS — Partial source inspection does not defeat the premise when the copy still removes discovery or narrows the inspected region, while a copy followed by every unchanged step adds its own costs and avoids none; the independent reliability benefit in premise 1 challenges the broader substitution-only commitment, not this conditional work-avoidance premise.
9. **The competing paths must be compared over the same validity window and for decision-equivalent answers, with quality differences represented among their failure or recovery costs.** — HOLDS — An apparently cheaper stale or lower-fidelity answer is not the same delivered value, and changing the horizon can move maintenance costs across the boundary; attempted counterexamples therefore changed the comparison target rather than defeating the premise.

## For the human
Look first at premise 1: checked materialization can pay as an independent error-detection channel even when it replaces no work, so the note's substitution-only condition needs to exclude or account for reliability value.
