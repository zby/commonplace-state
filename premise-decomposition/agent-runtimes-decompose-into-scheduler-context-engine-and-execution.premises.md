# Premise decomposition: Agent-runtime analysis should separate scheduling, context assembly, and external state

**Note:** kb/notes/agent-runtimes-decompose-into-scheduler-context-engine-and-execution.md
**Register:** claim
**Central commitment (one sentence):** For agent runtimes organized as repeated bounded model calls, analysis should separate scheduling, context assembly, and external state or action services as distinct causal responsibilities because the split localizes failures even when one implementation owns or spans those responsibilities.

## Premises and counterexamples

1. **In every runtime organized as repeated bounded model calls, scheduling and context assembly are sufficiently separable in the available causal evidence to support independent diagnostic attribution, even when one implementation owns both.** — DEFEATED — An end-to-end learned controller can make one opaque joint choice of the next operation, retrieved state, and prompt, exposing only the resulting call; if the controller has no separately inspectable or intervenable outputs, a wrong next step cannot be attributed to scheduling rather than context assembly, so the proposed split does not localize the responsible repair surface in this in-scope runtime. — GLOBAL — instance
2. **A wrong next step, missing or badly framed evidence, corrupted retained state, failed command, or boundary violation points to the responsibility named for that symptom.** — DEFEATED — A failed ingestion can leave a vector index stale, which presents at the model call as missing evidence but is repaired in external-state maintenance rather than context assembly; the symptom identifies where the failure appears, not necessarily where its cause or remedy lies. Qualifying these mappings as initial triage followed by cross-responsibility causal tracing preserves the three-part cut. — LOCAL — instance
3. **Grouping retained state, tool execution, and environmental boundaries into one external-services responsibility is sufficiently fine-grained to locate a useful remedy at the starting diagnostic stage.** — DOUBTFUL — When a sandbox rejects a command, the remedy may be a permission-policy change, a different scheduled operation, or context that tells the model which operations are authorized; the single external-services label does not distinguish these causes, and the note's concession that finer splits may be needed leaves the useful granularity unspecified. — LOCAL — instance
4. **Scheduling, context assembly, and external state or action name causally distinct decisions rather than merely distinct implementation components.** — HOLDS — A hunt through the note's overlapping cases did not collapse the questions: retrieval can both read external storage and select call-visible material, and tool support can both expose a schema and execute an action, but retention or execution can still vary independently of what is selected for a call, while call selection can vary independently of both.
5. **The retrospective practitioner mappings provide non-vacuous evidence that the three-part split exposes diagnostically useful hidden responsibilities.** — DOUBTFUL — The “Bounded Subagents” mapping assigns all three responsibilities, so the split alone leaves every proposed repair surface in play for that feature; because the coding permits multi-label assignment without a rule for excluding labels, successful re-expression does not by itself show diagnostic localization. This weakens the illustrative support without requiring the central commitment to be abandoned. — LOCAL — instance
6. **Repeated bounded calls necessarily create a control-progression question and a per-call input-selection question, while exact persistence and environmental effects occur outside the bounded model call.** — HOLDS — A hunt covering fixed schedules, API-managed threads, tool-free multi-call pipelines, and single-process implementations found shifts in who owns these responsibilities but no case in which finite call input, progression across calls, and exact persistence or effects became the same causal question.

## For the human

Look first at premise 1: the note's universal scope includes opaque joint controllers for which the proposed analytical split does not yield independently attributable repair surfaces.
