# Premise decomposition: What makes human-inclusive self-revision non-trivial?

**Note:** `kb/articles/what-makes-human-inclusive-self-revision-non-trivial.md`
**Register:** claim
**Central commitment (one sentence):** Human-inclusive self-revision requires a reusable path from criticism to an authorized operative successor that remains revisable even when revision machinery itself changes, and Commonplace currently provides broad but incomplete support for that path across repository-defined authority-bearing artifacts.

## Premises and counterexamples
1. **A human-inclusive general revision affordance can be established without representing maintainers' unarticulated judgment, so long as repository-defined authority-bearing artifacts and relations are addressable.** — DOUBTFUL — A maintainer team can make the decisive admission and warrant judgments through tacit norms or private deliberation, with repository artifacts serving mainly as record or implementation; in that case the real authority path is not fully represented even though the files are editable. — GLOBAL — instance
2. **Human-inclusive self-revision requires more than write access: it requires a reusable path that carries criticism through authorization and operative installation to a later-revisable successor.** — DOUBTFUL — A small repository can repeatedly revise its own prompts, rules, and validators through ordinary review-and-merge practice without an explicitly represented reusable path, and many readers would still count that as human-inclusive self-revision in practice. — GLOBAL — instance
3. **A revision path is only general if it remains available when the system revises the very artifacts that govern revision.** — HOLDS — An active counterexample hunt did not find a cleaner rival: a one-shot or self-disabling change would show change capacity, not the article's stronger general affordance.
4. **Commonplace represents enough repository-defined artifacts and relations that shape behavior for operators to inspect and selectively revise many authority-bearing paths.** — HOLDS — The article identifies live authority surfaces in contracts, instructions, ADRs, review criteria, validators, configuration, and code across several distinct cases.
5. **Commonplace can develop, warrant, install, and later revise successors on those represented paths rather than merely editing inert text.** — HOLDS — The cited ADR, validator, review-gate, and lifecycle cases show successors becoming operative and then serving as inputs to later revisions.
6. **The six examined paths are representative enough to justify the article's "broad but incomplete support" assessment.** — DOUBTFUL — Six handpicked paths may under-sample hidden but central authority routes such as generic maintainer admission, runtime model binding, deployment conventions, or dependency closure, so the breadth claim may outrun the current sample. — GLOBAL — prevalence
7. **The uncovered maintainer-admission and model-realization gaps show incompleteness rather than failures severe enough to negate the broader affordance claim.** — DOUBTFUL — If a later challenger cannot tell who was entitled to install an incumbent rule, or whether the recorded model identity matches execution, the criticism-to-authorized-successor path can fail on exactly the paths the article treats as load-bearing. — GLOBAL — instance

## For the human
Look first at premise 1: if tacit human judgment is itself part of the authority path, the article's repository-scoped addressability test may miss the hardest part of human-inclusive self-revision.
