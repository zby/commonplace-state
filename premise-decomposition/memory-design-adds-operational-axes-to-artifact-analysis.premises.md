# Premise decomposition: Memory design adds operational axes to artifact analysis

**Note:** `kb/notes/memory-design-adds-operational-axes-to-artifact-analysis.md`
**Register:** claim
**Central commitment (one sentence):** Memory-system design needs explicit operational policy axes on top of artifact analysis by substrate, representational form, lineage, and behavioral authority.

## Premises and counterexamples
1. **Artifact fields alone do not capture all design-relevant variation in how retained material becomes future capacity.** — HOLDS — The note's core comparison survives active counterexample hunt: systems can match on substrate, form, lineage, and use-time authority yet still differ materially in what gets written, how it is transformed, when it is activated, and how it changes over time.
2. **At least some operational policy choices remain open after artifact fields are fixed.** — HOLDS — A fixed artifact description still leaves multiple live choices about capture triggers, derivation, activation path, retirement, and assessment, so artifact identity does not by itself settle the memory design.
3. **The named questions about capture, derivation, activation, authority assignment, lifecycle, and evaluation are recurring comparison questions at the memory-system level rather than one-off implementation details.** — HOLDS — Active counterexample hunt did not find a plausible reading on which these questions disappear once the system is treated as a memory system rather than as a bare storage primitive.
4. **Each named operational axis is substantive enough to deserve explicit treatment as part of memory design.** — DOUBTFUL — `evaluation` is the weak point: a minimal but still recognizable memory design can operate as a human-curated standing-context file or append-only working memory without an explicit success-measure beyond ordinary user judgment, so the claim that every named axis must be treated explicitly looks stronger than the note fully earns. — LOCAL — instance
5. **Starting memory comparison from storage format, representational form, or mechanism labels alone can hide consequential differences that the operational axes surface.** — HOLDS — Concrete design alternatives with the same artifact labels but different write triggers, activation timing, or retirement policy remain easy to construct, and those differences plausibly matter to behavior.

## For the human
Look first at premise 4: if `evaluation` is meant as a universal required axis, the note should defend that more directly or narrow the commitment to say these axes are a strong recurrent checklist rather than an always-needed full set.
