# Premise decomposition: A research program for learning software factories

**Note:** kb/articles/a-research-program-for-learning-software-factories.md
**Register:** claim
**Central commitment (one sentence):** The proposed staged research program can determine whether an LLM-based software factory learns from its own production through acquired, held, and revised natural-language project theory by showing experience-dependent improvement in an operative successor while model weights remain fixed.

## Premises and counterexamples
1. **Universal (undeclared): a predeclared comparison over prior capabilities, one target improvement, and repeatable factory development can establish that an operative successor is genuinely better than its predecessor.** — DEFEATED — A successor can preserve every sampled prior task, exceed the declared target by optimizing an inspectable benchmark, and still lose an unsampled capability needed by ordinary members of the declared software family; the article also concedes that family-level evaluation is expensive, inspectable tests are gameable, and decisive human judgment changes the learner boundary, so it presently has no trustworthy oracle that excludes this case. — GLOBAL — instance
2. **Universal, bounded to the acquisition condition: constructing a recoverable theory, changing modifications when it is withheld or replaced, and revising it after consequences identifies project theory acquired from production experience.** — DEFEATED — An LLM can infer the same design account from static code and pretrained software patterns before any informative production episode, write that account when asked, use it causally, and later edit it after feedback; all the stated probes pass even if the production record did not cause the theory's acquisition. The condition needs a production-evidence intervention or counterfactual experience contrast, not only the holding probes. — GLOBAL — instance
3. **Universal, bounded to the successor experiment: supplying versus withholding the predecessor's retained production record and theory identifies the contribution of the predecessor's production experience beyond the task specification.** — DOUBTFUL — Both arms receive the incumbent factory, whose tests, tools, workflows, and code can already embody the very production experience under study; for example, a defect-induced validator installed before the experiment remains operative in both arms even when the record that caused it is withheld. The contrast estimates the marginal value of the separately supplied record and theory, not the total causal contribution of predecessor experience. — LOCAL — instance
4. **Universal, bounded to experiment one: success on an uncued modification demand shows that the system recognized the relevance of project theory rather than following a benchmark cue or generic retrieval signal.** — DOUBTFUL — A novel requirement can repeat an unusual identifier or domain phrase found only in the supplied theory, causing ordinary lexical retrieval to surface it even though the system cannot relate a semantically equivalent paraphrase to the project's organization. Calling the demand ordinary and enlarging the corpus does not exclude that leakage; adversarial paraphrases or cue-matched controls are needed. — LOCAL — instance
5. **Universal, bounded to the stated theory interventions: theory-present, theory-withheld, fact-matched, and wrong-theory arms isolate the causal contribution of theory-level organization rather than generic context or steering effects.** — DOUBTFUL — The fact-matched arm removes relations, purposes, and scope conditions, which are additional information, while a plausible wrong theory introduces conflict and distraction; a performance difference can therefore arise from information quantity, coherence, or attention allocation without establishing the stronger project-theory construct. The article acknowledges that the current arm identifies the supplied organization only as a bundle. — LOCAL — instance
6. **Existential (stated as a working hypothesis): natural language can carry enough project theory to coordinate consequential changes across the heterogeneous machinery of at least one LLM-based software factory while remaining separately manipulable.** — HOLDS — The strongest attempted counterexample is a cross-component invariant whose exact enforcement lives only in types, tests, or executable checks, but that defeats natural language as the sole enforcement substrate, not the narrower possibility that prose carries the purposes and relations used to coordinate changes while formal artifacts enforce their consequences; no impossibility witness was found.
7. **Universal, bounded to the fixed-weight contrasts: holding model weights fixed excludes model training as the route by which treatment differences arise.** — HOLDS — Sampling variance and silent provider model updates could mimic a treatment effect, but randomized replication and a pinned model snapshot are ordinary protocol controls rather than counterexamples to the premise as stated; changes mediated by prompts, retained artifacts, tools, or workflows are the non-weight route the program intends to measure.
8. **Universal (undeclared): evaluation-guided revision followed by adoption and later dependence is required to distinguish a better candidate factory from a learned successor factory.** — HOLDS — A candidate that scores well but is never installed, or is installed but never used by later production, is the strongest attempted counterexample; neither realizes a retained operative change on which later work depends, so neither meets the article's declared factory-learning construct.
9. **Universal, bounded to experiment one: a product-level theory-holding result is only a component result and does not by itself establish factory-level learning.** — HOLDS — Even a system that repeatedly extends a product through its existing abstractions has not thereby modified reusable production machinery; no counterexample was found that turns modification of the produced software alone into a retained change of the factory under the article's declared boundary.
10. **Universal, bounded to one accepted successor: one experience-dependent improvement establishes at most one learning transition, not recurrent compounding or recursive self-improvement.** — HOLDS — A successor may outperform its predecessor and retain the machinery that produced it yet fail on its very next attempt to construct another successor; this defeats a compounding inference but not the article's deliberately bounded one-transition claim.

## For the human
Look first at premise 1: the article's acknowledged oracle problem means the successor experiment cannot yet establish the genuine improvement on which its headline learning claim depends.
