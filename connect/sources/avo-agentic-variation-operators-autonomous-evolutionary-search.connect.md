**Candidate evaluation:**

- Kept the proposal-selection note because AVO explicitly exposes candidate search, reject-capable correctness/performance evaluation, and git/lineage retention; reflection is not required by that note.
- Kept the fixed-decomposition note because AVO expands agency inside `Vary` while fixing the seed, scoring function, evaluator, benchmark partition, model, tools, knowledge base, single-lineage policy, commit rule, and supervisor mechanism. Its benchmark improvements cannot validate those fixed choices.
- Kept representational-form coevolution as a bounded evidence candidate because AVO adds a fixed-weight, agent-mediated symbolic-code search case, while rejecting any stronger claim that it coevolves all forms.
- Kept HGM because its descendant-productivity result directly challenges AVO's single-lineage, immediate-score, non-regressing commit policy as a generally adequate search allocation rule.
- Kept Frontis-MA1 because its fixed Draft/Improve/Debug/Crossover basis is the nearest local contrast to AVO's claim that a general coding agent should subsume prescribed variation operators.
- Kept the code-grounded Meta-Harness review as the closest inspected analogue: both let a coding agent use retained code and execution evidence to write evaluated successors, while Meta-Harness makes the trace store, proposer instructions, manifests, and frontier mechanics inspectable.
- Rejected the theory-mediated-learning note because the MHA-to-GQA adaptation does not expose an addressable theory as a causal intermediate, count target observations, or separate theory reuse from code reuse and additional search.
- Rejected warranted autonomy as a direct evidence edge because its stated frame is self-improvement, whereas AVO improves an external kernel rather than the variation operator's own behavior-determining organization. Its hard-oracle lesson remains useful in the ingest limitations without claiming category membership.
- Rejected Autogenesis and Exo as regular agentic-system edges: their self-modifying protocol/executor boundaries differ materially from AVO's external-program optimization target. The similarity is only broad reflective/evolutionary vocabulary.

**Link following:**

- Followed the proposal-selection note to oracle domain, accumulation/compounding, behavioral authority, and the self-improving-system boundary. This confirmed that AVO is a clean non-reflective proposal-selection instance but not automatically a self-improving one.

## Connections Found

- [A proposal-selection improvement loop requires search, evaluation, and operative retention](../../../../notes/a-proposal-selection-loop-requires-search-evaluation-and-retention.md) -- **is-evidence-for**: AVO is a non-reflective program-optimization instance in which an agent searches through code edits, failed or non-improving candidates are rejected, and accepted kernels become the committed lineage used by later variation.
- [Learning inside a fixed decomposition inherits its mistakes](../../../../notes/learning-inside-a-fixed-decomposition-inherits-its-mistakes.md) -- **rests-on**: interpreting AVO's gains requires separating the broad edit-and-diagnosis space placed inside the agent from the fixed evaluator, task representation, benchmark suite, seed, model/tool surface, single-lineage rule, commit gate, and supervisor outside it.
- [Treat continual learning as representational-form coevolution](../../../../notes/treat-continual-learning-as-representational-form-coevolution.md) -- **is-evidence-for**: AVO adds a fixed-weight agent that learns by retaining and revising symbolic code under execution feedback; it expands the existing FunSearch/Meta-Harness family without establishing cross-form coevolution.
- [Ingest: Huxley-Gödel Machine](../../../../sources/huxley-godel-machine-human-level-coding-agent-development.ingest.md) -- **compares-with**: HGM finds immediate benchmark score can mis-rank future lineage productivity, while AVO deliberately keeps one lineage and commits only candidates that match or improve the current suite.
- [Ingest: Frontis-MA1](../../../../sources/frontis-ma1-training-ai4ai-recursive-self-improvement.ingest.md) -- **compares-with**: Frontis fixes Draft/Improve/Debug/Crossover and an evolutionary controller; AVO's central intervention is to replace such prescribed variation structure with a self-directed agent, while leaving the outer scoring and retention boundary fixed.
- [Meta-Harness](../../../../agent-memory-systems/reviews/meta-harness.md) -- **compares-with**: this inspected trace-to-code loop makes durable histories, proposer instructions, candidate manifests, validation, and frontier ranking visible, providing the closest code-grounded comparison for AVO's paper-only claim that lineage, knowledge, and execution feedback support agent-directed variation.
