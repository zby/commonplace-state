# Connection Report: How to Write a 21st Century Proof

**Source:** [How to Write a 21st Century Proof](../../../../sources/.snapshots/lamport-how-to-write-a-21st-century-proof.md) (Leslie Lamport, 2011/2012; `https://lamport.azurewebsites.net/pubs/proof.pdf`)

**Authored surface.** The target is an immutable snapshot under the ignored `.snapshots/` tree. Per `kb/sources/COLLECTION.md` ("Snapshots are immutable local inputs … the snapshot itself is never the link author") the outbound candidates below are recommendations for the **not-yet-existing** ingest `kb/sources/lamport-how-to-write-a-21st-century-proof.ingest.md`, not for the snapshot. See Flags.

**Source claim as read.** Prose proofs hide their own logical structure, so (a) the reader cannot tell which sentences assert and which justify, and which prior facts a justification uses; (b) the writer is not forced to produce a justification per assertion and so misses gaps. Hierarchical numbered steps plus naming of every fact fix both: each step becomes a claim with an explicit justification citing named grounds, hierarchical numbering restricts which names a step may legally cite, and a mandatory Q.E.D. last step forecloses proofs that never reach what was to be shown. How far to expand a step is set by the checker — "if the truth of a statement is not completely obvious … more detail is needed"; a beginning student needs more than a mathematician; levels run about 4–10 steps. Structure makes error elimination *possible, not inevitable*. Learning the fully formal (TLA+/TLAPS) form teaches the informal one, but machine-checked proofs remain impractical for decades.

**notes** (`is-evidence-for` — bears materially on the target claim without asserting the target has incorporated it)

- [Structured output is easier for humans to review](../../../../notes/structured-output-is-easier-for-humans-to-review.md) — **is-evidence-for**: the note argues from readability alone that separating assertion from justification turns one holistic judgment into focused per-part checks, and reaches for "scientific papers are easier to review than essays" as its only illustration; Lamport supplies twenty years of practitioner evidence for exactly that mechanism in a genre where the check has a truth condition, including a referee who reports the structure was "the only way to present long proofs … both detailed and readable".
- [Human writing structures transfer to LLMs because failure modes overlap](../../../../notes/human-writing-structures-transfer-to-llms-because-failure-modes.md) — **is-evidence-for**: the note claims writing genres evolved to prevent specific reasoning failures and must be evaluated per convention. Lamport names the failures the prose-proof convention permits (an assertion whose function is unmarked, a justification whose grounds are unstated, an unstated hypothesis such as `a < b`, a first step that cannot be proved) and the structural convention introduced against each — a worked per-convention case rather than an analogy.
- [Soft-bound traditions as sources for context engineering strategies](../../../../notes/soft-bound-traditions-as-sources-for-context-engineering-strategies.md) — **is-evidence-for**: the note's twelve-row table has no row for mathematical proof writing. This source supplies the missing row in the table's own terms — bounded processor: the step's checker; the bound: what that checker can accept as obvious in one look; adaptation mechanism: hierarchical decomposition plus naming, with the level expanded until the checker stops asking why. Following the link tests the survey's coverage claim.
- [Short composable notes maximize combinatorial discovery](../../../../notes/short-composable-notes-maximize-combinatorial-discovery.md) — **is-evidence-for**: the note justifies one-claim atomicity by bounded-context co-loading. Lamport reaches a rule of the same shape from a different justification — the unit is sized so its checker can decide it (levels of about 4–10 steps, expansion continuing while any doubt remains) — which is evidence that atomicity has a second, independent warrant the note does not currently carry.
- [Warranted autonomy is bounded by oracle domain](../../../../notes/warranted-autonomy-is-bounded-by-oracle-domain.md) — **is-evidence-for**: the note bounds warranted evaluation by what an oracle can assess at the required confidence. - [An insufficient summary precedes the source rather than replacing it](../../../../notes/an-insufficient-summary-precedes-the-source-rather-than-replacing.md) — **is-evidence-for**: Lamport separates the proof sketch from the proof ("Proof sketches are fine, but they are not proofs") and describes the layout the note predicts — the sketch is published, the full proof stays reachable behind it (journal appendix, then a Web link), because the sketch cannot license a stop for the reader who must check.

- [Generation confidence does not by itself certify soundness](../../../../notes/generation-confidence-does-not-by-itself-certify-soundness.md) — **is-evidence-for**: the human-side statement of the note's separation. "When you write a proof, you believe the theorem to be true. The only way to avoid errors is to be ruthlessly suspicious of everything you believe" — the author's confidence is the thing the per-step check exists to defeat, not an input to it.
- [Process structure and output structure are independent levers](../../../../notes/process-structure-and-output-structure-are-independent-levers.md) — **is-evidence-for**: a case where the two levers are coupled rather than independent. Constraining the *output* (numbered steps each carrying a justification; a mandatory Q.E.D. step) is reported to change the *process*: "Writing the structured proof of Figure 3 forced us to write a justification for each step." - [Claim notes should use Toulmin-derived sections for structured argument](../../../../notes/claim-notes-should-use-toulmin-derived-sections-for-structured.md) — **is-evidence-for**: each Lamport step is a claim plus an explicit justification naming the grounds it uses, applied recursively so a justification too long for one line becomes a sub-proof rather than a lemma. - [Title as claim enables traversal as reasoning](../../../../notes/title-as-claim-enables-traversal-as-reasoning.md) — **is-evidence-for**: Lamport's second principle is naming — every fact gets a name so a step can cite exactly which facts it uses — and hierarchical numbering adds a *scoping* rule the note lacks: a step may cite only names visible at or above its level, because a step proved under an `assume` does not hold outside it. - [A knowledge base should support fluid resolution-switching](../../../../notes/a-knowledge-base-should-support-fluid-resolution-switching.md) — **is-evidence-for**: the hypertext structured proof is a mechanism instance — the reader sees the corollary, opens the five steps, opens individual sub-proofs, and "can stop opening lower levels of the proof when satisfied", with the paper fallback (indentation) named as the degraded case.
- [Design for the first-time human, except on access cost](../../../../notes/design-for-the-first-time-human-except-on-access-cost.md) — **is-evidence-for**: Lamport writes to the competent newcomer by default ("a beginning student needs more help understanding a proof than does a mathematician") and resolves the note's access-cost carve-out structurally: the extra detail is present but collapsed, so the expert is not charged for it and the newcomer is not denied it.
