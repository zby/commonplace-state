- [HarnessEvolve](../../../../sources/harnessevolve-reference-trajectories.ingest.md) — **compares-with**: both inspect successful and failed executions to propose runtime changes. ModularRSI adds same-task historical-success retrieval, cross-task voting and module-restricted evolution on separately curated tasks. It lacks a dedicated contrast-removal ablation, so its gains do not independently establish that contrastive analysis caused the improvement.

## Rejected Candidates

- Five-module optimality: alternatives change evolution scope and aggregate work, and no alternative five-way decomposition is tested.
- Program/execution checks as behavioral improvement acceptance: the described execution gate checks runtime errors and protocol validity on two tasks, not a strict reward increase.
- A decreasing mixed-success rate as proof of causal repair: changing task outcomes can have multiple causes; the paper explicitly acknowledges no isolated contrastive-analysis ablation.
- Instance-disjoint as domain-agnostic: construction uses benchmark category labels as search guidance; the claimed independence concerns instances and task-specific information.

## Flags

The released pool has 2,000 tasks, but main evolution uses 120 per source subset. The principal modular comparison gives each independent module three epochs plus integration; single-module gains do not remove the full treatment's aggregate-budget difference. The separate AHE/Meta-Harness comparison matches aggregate epochs at 16, uses a different DeepSeek version, and disables web search, so keep its baseline apart from the main tables. Three downstream rollouts do not establish repeated evolution-seed uncertainty. Later case traces contain other updates and are explicitly not single-edit causal tests.
