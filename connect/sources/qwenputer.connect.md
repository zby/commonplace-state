## Connections Found

These are recommendations for the eventual ingest, not snapshot edits.

- [Code complements the weight–prompt pair with independently executed symbolic operations](../../../../theory/code-complements-weight-prompt-with-symbolic-operations.md) — **compares-with**: Qwenputer connects to this note because compiler-assigned CPU transitions separate choosing a calculation from carrying it out, while moving the rule-following executor inside model forward passes rather than an external runtime. The reader gains a test of the note's operation distinction without equating all weights with learned interpretation.
- [Unified calling conventions enable bidirectional refactoring](../../../../theory/unified-calling-conventions-enable-bidirectional-refactoring.md) — **compares-with**: Qwenputer connects to this note because its reuse of a pretrained tool-call format lets an internal compiled executor present familiar requests and responses. This compares interface continuity across implementation placement; the report does not demonstrate llm-do-style dynamic dispatch or reversible refactoring.
- [Representational form](../../../../theory/definitions/representational-form.md) — **defined-in**: Qwenputer connects to this definition because its compiled circuit and one-hot addressed state require classification by operational semantics and localization, not merely by being numerical state inside a neural model. Separate learned Qwen parameters, fixed circuit rules, directory structure, and stored text before assigning a form.
- [Storage substrate](../../../../theory/definitions/storage-substrate.md) — **defined-in**: Qwenputer connects to this definition because the model checkpoint, live recurrent matrix, and saved state have different persistence and access roles. A filesystem-shaped interface does not mean files are stored in an ordinary external filesystem or in learned model parameters.
- [Explicit retention provides direct targets for selective revision](../../../../theory/only-explicit-retention-is-durable-writable-and-addressable.md) — **compares-with**: Qwenputer connects to this note because put/append/get/list/delete and cross-chat state reload supply an unusually concrete operation profile for numerical model state. Named-file editing does not establish selective revision of a semantic commitment or absence of collateral behavioral effects.
- [KBLaM](../../../../agent-memory-systems/reviews/KBLaM.md) — **compares-with**: Qwenputer connects to KBLaM because both put memory access inside model computation without serializing the entire store into the text prompt. KBLaM injects encoded records through modified attention, whereas Qwenputer reports exact internal addressing and mutable recurrent-state files. This distinction changes inspection and update tests.
- [Nested Learning](../../../../sources/nested-learning-the-illusion-of-deep-learning-architecture.ingest.md) — **compares-with**: Qwenputer connects to this ingest because it contrasts compiler-assigned exact row updates with learned associative memories at multiple update frequencies. Internal location and persistence cadence do not determine whether stored content is approximate or individually addressable.
- [The Equations of Reasoning](../../../../sources/pathway-equations-of-reasoning.ingest.md) — **compares-with**: Qwenputer connects to this ingest because both describe fast model-internal memory, but Pathway's Hebbian state is not a reported exact file store and its essay does not claim cross-run fast-state persistence. Qwenputer reports explicit save/load continuity instead.
- [The Price of Meaning](../../../../sources/the-price-of-meaning-why-every-semantic-memory-system-forgets.ingest.md) — **compares-with**: Qwenputer connects to this ingest because exact one-hot access is a candidate non-semantic access path outside the ingest's kernel-threshold interference regime. Exact bytes would not remove the model's separate problem of choosing the correct filename or using returned facts faithfully; applying the theorem requires checking its actual assumptions.
- [Qwenputer original article](https://divagr.com/blog/qwenputer) — **derived-from**: the eventual ingest analysis is worked out from this captured practitioner report. This identifies its source, not independent confirmation of implementation or benchmark claims.

## Flags

- The connection set spans execution/interface design, memory representation/persistence, and governance limits, and the source makes several independent assertions. Treat the future ingest as a split candidate if it turns these into five or more substantive theory connections across those areas. Preserve the captured source unchanged; separate future claims by reader need rather than reproducing a broad related-links spray.
- Do not treat 18 million CPU instructions, roughly 230,000 replayed output positions, or the small arithmetic comparisons as verified guarantees. File-memory percentages use different stated comparisons and do not establish general memory reliability.
- “No external tool calls” does not mean no host runtime support. The source requires RvChat to load firmware and isolate trace tokens, and reports that plain `generate()` is insufficient.
- Named-file addressability, exact retrieval, semantic selection, persistence, and record authority are separate properties. A future ingest should preserve those distinctions and the experimental status of the filesystem branch.
