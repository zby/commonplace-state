**Candidate evaluation:**

- Kept the Bitter Lesson production-method note because the paper supplies its
  bounded learned-localized instance: parametric reinforcement learning and tree
  search produced small symbolic routines later incorporated into LLVM libc++.
- Kept the proposal-selection note with a scoped socio-technical reading. Search
  constructs assembly-program candidates, correctness and performance can
  prevent selection, and reviewed winning routines become operative in the
  library. The network's gradient updates are a separate direct-update mechanism.
- Kept the verifiability gradient because exhaustive fixed-sort inputs, sampled
  variable-sort tests, program-length proxies, and replicated latency
  measurements show distinct evaluator strengths and limits inside one system.
- Kept fixed decomposition as a comparison, not a failure claim. AlphaDev fixes
  the x86 instruction subset, pruning rules, task families, representations,
  rewards, test inputs, and deployment translation while optimizing within them.
- Kept FunSearch and AVO as the closest localized-program-search comparisons.
  They vary the proposal machinery and retention path without implying that one
  system transfers the others' mechanism.
- Rejected representational-form coevolution as direct evidence: code generated
  during search contributes training experience and final symbolic output, but
  the paper does not establish a persistent two-form update loop in which both
  retained forms continue to revise one another.
- Rejected exact-implementation and proximate-target notes as direct evidence:
  correctness and latency are separate criteria here, but the paper does not
  isolate a requirement-to-objective mismatch or show that the chosen latency
  target failed to serve its objective.

**Link following:**

- Followed the Bitter Lesson production-method note to proposal selection,
  representational-form coevolution, localized retention, and fixed
  decomposition. This confirmed that AlphaDev establishes existence in the
  learned-localized cell, not scaling across a heterogeneous artifact corpus.
- Followed proposal selection to oracle strength and operative retention. The
  paper contains both within-search reward feedback and an external review and
  library-adoption path; only the latter makes the final routine operational for
  downstream users.
- Followed FunSearch and AVO to their evaluator and update-space boundaries.
  FunSearch keeps its pretrained LLM frozen and evolves task-bound functions;
  AVO gives a coding agent broader variation control but still fixes its score,
  seed, tool surface, and lineage policy.

## Connections Found

- [The bitter lesson selects production methods, not representational forms](../../../../notes/the-bitter-lesson-selects-production-methods-not-representational.md) -- **is-evidence-for**: AlphaDev is a bounded learned-localized instance in which reinforcement learning and tree search produce symbolic assembly routines, and reviewed routines become operative in LLVM's standard C++ library.
- [A proposal-selection improvement loop requires search, evaluation, and operative retention](../../../../notes/a-proposal-selection-loop-requires-search-evaluation-and-retention.md) -- **is-evidence-for**: at the program-and-deployment level, AlphaDev searches assembly sequences, correctness and performance evaluation can reject candidates, and selected routines are retained in libc++; this does not turn every underlying gradient update into proposal selection.
- [The verifiability gradient](../../../../notes/verifiability-gradient.md) -- **is-evidence-for**: AlphaDev combines exhaustive correctness checks for small fixed sorts, predefined test sets for variable routines, program length as a proxy where justified, and replicated measured latency where the proxy breaks down.
- [Learning inside a fixed decomposition inherits its mistakes](../../../../notes/learning-inside-a-fixed-decomposition-inherits-its-mistakes.md) -- **compares-with**: AlphaDev improves programs inside a supplied instruction vocabulary, pruning regime, representation, correctness setup, latency objective, and deployment path; its gains do not test alternatives outside that effective update space.
- [FunSearch ingest](../../../../sources/mathematical-discoveries-program-search-large-language-models.ingest.md) -- **compares-with**: both use parametric search machinery to produce localized executable artifacts under strong evaluators, while FunSearch freezes its LLM and retains a scored program population whereas AlphaDev trains its policy/value network and ultimately deploys selected routines through libc++ review.
- [AVO ingest](../../../../sources/avo-agentic-variation-operators-autonomous-evolutionary-search.ingest.md) -- **compares-with**: both search low-level performance code with correctness and measured-speed feedback, but AVO delegates variation and diagnostic control to a coding agent over a retained lineage while AlphaDev learns a policy/value guide over AssemblyGame.
